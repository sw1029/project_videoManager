# ADR-0018 실제 요구 반영 검수기와 유지 요소 검수기

- 상태: 채택 (2026-11-12)
- 관련: US-06 (요구사항 반영 확인), US-03 (AC-33), US-01 (AC-01), 성공 지표 1·2, ADR-0015·0016·0017
- 검토 기록: [docs/research/concept-ux-review.md](../research/concept-ux-review.md)

## 맥락
- 컨셉 화면의 '03 검수·수정' 은 "컵 색상 불일치" 경고와, 수정 뒤 이미지의 '인물·배경 유지' 표시를 보여 준다.
  TO-BE 시나리오의 핵심도 "구상한 내용이 얼마나 반영됐는지 수치로 표시" 다 (지표 2: 충족한 요구사항 수 ÷ 전체 요구사항 수).
- 요구 반영(REQUIREMENT) 검수기는 Fake 뿐이었다. 클립을 보지 않아 항상 PASS 다. 1차 실호출 5회차에서 컵이 요구(청록)와 달리
  빨갛게 나왔을 때도 요구 반영 검수는 13건 모두 PASS 였다. 일관성 검수(`vlm_consistency`)가 '고정 속성 이탈' 로 잡았지만,
  그것은 객체의 고정 속성만 보고 장면 조건·행동·관계는 보지 않으며, 어느 요구조건이 어긋났는지를 요구조건 단위로 주지 않는다.
- 보존(PRESERVATION) 검수는 SSIM(`ssim_preservation`)이 있다. 화면 전체의 구조 유사도라서, 편집 모델이 프레임을 다시 그리기만 해도
  깎인다 (1차: 눈으로는 컵 색만 바뀐 장면이 0.745). 지표 1 의 정의는 "지정하지 않은 대상의 **속성** 변경 비율" 이고,
  컨셉의 '유지할 요소' 는 요소 단위다.
- 제약은 그대로다: GPU·큰 패키지 없이 API 와 ffmpeg 로 동작한다 (ADR-0015).

## 결정

### 1. `vlm_requirement` (REQUIREMENT, 지표 2)
- 장면마다 표본 프레임을 고르게 뽑고(`FRAME_REQUIREMENT_FRAMES`, 기본 3) **장면 하나당 VLM 을 한 번** 부른다.
  그 장면의 요구조건마다 프레임별로 yes / no / unclear 와, 화면에서 실제로 본 것(`observed`)을 받는다.
- 판정
  - 고정 속성·장면 조건(색·의상·문구·장소·조명 등): 판정된 프레임 가운데 yes 의 비율이 임계값
    (`FRAME_REQUIREMENT_THRESHOLD`, 기본 0.5) 이상이면 PASS. 점수는 그 비율이다.
  - 행동·자세·표정·위치와 관계(들고 있다 등): 한 프레임이라도 yes 면 PASS. 장면 안에서 한 번 보이면 된다.
  - 판정된 프레임이 없으면(모두 unclear) UNDETERMINED.
- FAIL 이면 어긋난 프레임이 대표하는 구간(행동·관계는 장면 전체)에 경고를 남긴다. 메시지는
  `cup color: 요구 'teal', 화면: red ceramic mug` 꼴이다. 결과에는 `requirement_key`·`entity_key`·`scene_key` 가 있고
  `detail` 에 술어·요구 값·본 것·프레임별 판정이 있어, 화면이 문장을 해석하지 않고 "컵 색상 불일치" 를 만들 수 있다.
- **이 버전에서 값이 바뀐 요구조건에는 예전 값을 붙여 보낸다**: `red_mug — color: teal (changed in this version; it was "red" before)`.
  객체의 키·설명과 다른 요구조건의 문구에는 예전 표현이 남는다. 실호출에서 객체 키가 `red_mug` 인 컵의 색을 teal 로 바꾼 뒤
  한 장면이 "teal, not red" 라는 이유로 FAIL 이 됐다. 그 장면에 없던 고정 속성(모든 등장 구간에 적용하며 더해진 것)은
  같은 객체가 다른 장면에서 갖던 값을 예전 값으로 쓴다. 행동·자세와 관계는 장면마다 다른 것이 정상이라 견주지 않는다.
  지시문에도 이름·설명은 낡았을 수 있는 표지이고 요구조건이 우선한다는 것을 예와 함께 적는다.
- **다시 만들지 않은 장면은 부모 버전의 판정을 물려받는다** (`detail.inherited_from`). 같은 클립을 다시 물으면 답이 흔들려
  바뀌지 않은 장면의 판정이 버전마다 달라질 수 있고(1차: 같은 클립에 0.5 와 0.83), 호출 비용도 든다.
  부모에 그 요구조건의 판정이 없으면 새로 판정한다. 이를 위해 검수 컨텍스트에 부모 버전의 검수 결과(`parent_checks`)를 싣는다.

### 2. `vlm_preservation` (PRESERVATION, 지표 1)
- 다시 만든 장면마다 부모 클립과 자식 클립에서 **같은 시각의 프레임**을 뽑아(`FRAME_PRESERVATION_FRAMES`, 기본 2쌍)
  장면 하나당 VLM 을 한 번 부른다. 요소마다 **다른 점을 먼저 적게 한 뒤** yes(그대로) / no(달라짐) / unclear 를 받는다.
- 같은 시각의 프레임끼리 짝지어 견주게 하고(B1 과 A1), 요소의 뜻을 좁게 적는다: 동작 = 같은 몸짓·손과 팔의 위치·화면 안 위치,
  형태 = 같은 모양·비율·화면 안 크기, 배경 = 같은 물건이 같은 자리에. 비슷한 내용으로 다시 찍은 장면은 달라진 것이다.
  처음에는 판정을 먼저 받고 뜻도 느슨했다. 실호출에서 새로 생성돼 자세·구도가 달라진 두 장면의 8건이 모두 '그대로' 로 나왔다.
- 볼 요소
  - 수정 요청에 유지할 요소(ADR-0017)가 있으면 그 장면에 해당하는 것.
  - 없으면 기본 요소: 바꾸지 않은 객체의 모습(배경 객체 제외)과 장면의 배경.
  - 이 수정이 바꾸려는 것(요구조건의 차이, REPAIR 면 바로잡으려는 요구조건)은 "달라져야 하는 것" 으로 따로 알려 준다.
- 요소 하나가 결과 하나다: yes → PASS(1.0), no → FAIL(0.0) + 그 장면 구간 경고(`barista: 동작이(가) 달라짐 (…)`), unclear → UNDETERMINED.
  부모 클립을 그대로 쓴 장면은 1.0, 원본 버전에는 결과가 없다 (다른 보존 검수기와 같다).

### 3. 공통 규약
- 판정할 수 없으면 UNDETERMINED 다: 클립이 영상이 아님, 비교할 부모 클립이 없음, VLM·ffmpeg 호출 실패, 응답에 그 항목이 없음.
  VLM 장애로 버전을 FAILED 로 만들지 않는다 (ADR-0015 와 같다).
- 요구조건·프레임·요소를 R1 / F1 / E1 로 짧게 가리키고, 응답 항목은 공용 규칙(`adapters/vlm_answers.py`)으로 맞춘다.
  실제 모델은 키에 질의의 한 줄을 통째로 돌려줄 때가 있다 (1차 실호출).
- 토큰 수는 장면의 첫 결과에만 적는다 (장면당 한 번 부른 호출이다).

## 결과
- `FRAME_CHECKERS=vlm_requirement,vlm_consistency,vlm_preservation` 으로 세 지표를 모두 실제 영상으로 잰다. 기본값은 Fake 그대로다.
- 비용 (gpt-4.1, 480p 프레임): 요구 반영은 장면당, 유지 요소는 다시 만든 장면당, 일관성은 객체당 한 번.
  2차 실호출에서 3~4장면 영상의 검수가 6~7회 호출, 입력 약 14,400~17,500·출력 약 1,000~1,300 토큰이었고 14~16초 걸렸다.
- 한계
  - VLM 한 번의 판정이다. 임계 근처에서는 흔들릴 수 있다. 물려받기는 그 흔들림이 버전 사이로 번지는 것만 막는다.
  - 유지 요소 판정은 여전히 사람 눈보다 너그럽다. 새로 생성된 '들어 보이는 장면' 에서 동작은 FAIL 로 잡았지만
    구도가 조금 달라진 배경과 조금 작아진 컵은 '그대로' 로 봤다. 요소 단위의 큰 변화를 알리는 용도다.
  - `preservation_rate` 는 PRESERVATION 결과의 평균이다. `vlm_preservation` 과 `ssim_preservation` 을 함께 켜면 요소 판정(0/1)과
    SSIM 값이 한 평균에 섞인다. 지표로는 하나만 켜고, 함께 켤 때는 `detail.method`(`vlm_keep` / `ssim`)로 나눠 본다.
  - 요구조건이 많은 장면은 한 번의 호출에 판정이 몰린다. 표본 프레임 3장으로는 짧은 동작을 놓칠 수 있다.
  - 일관성 검수(`vlm_consistency`)와 겹치는 판정(객체의 고정 속성)이 있다. 일관성은 장면 **사이**의 같음을 보고, 요구 반영은 장면 **안**의 충족을 본다.

## 대안
- 일관성 검수기의 속성 판정을 요구 반영 결과로도 내보내기: 장면 조건·행동·관계가 빠지고, 객체당 호출이라 요구조건 단위로 나누기 어렵다.
- 요구조건마다 따로 호출: 판정은 독립적이지만 호출 수가 요구조건 수만큼 늘어난다 (3장면 13건 → 13회). 장면 단위로 묶었다.
- 보존을 마스크 SSIM 으로: 변경 영역(추적 박스·마스크)을 빼고 재면 공정하지만 실제 추적기가 선행돼야 한다 (AC-34). 후속.
- 임베딩 유사도(CLIP·DINO)로 요소 유지 판정: 큰 설치가 필요하고 '동작'·'조명' 같은 요소를 가르기 어렵다. 후속 (ADR-0015).

## 검증
- 단위·통합 테스트 (네트워크 없이, 진짜 ffmpeg): `tests/unit/test_vlm_requirement_checker.py`, `tests/unit/test_vlm_preservation_checker.py`,
  `tests/integration/test_requirement_checks_pipeline.py`(불일치 감지 → REPAIR → 다시 만든 장면만 재판정, 유지 요소 판정),
  `tests/unit/test_identity_config.py`(설정).
- 실호출 (2026-11-12, 연구 문서 §5)
  - 요구는 청록인데 빨간 컵이 나온 클립: 컵 색 요구조건 2건을 FAIL(0.0)로 판정하고 `화면: red ceramic mug` 를 남겼다. 반영률 11/13.
  - 다시 맞춘 뒤: 컵 색 2건 PASS. 다시 만들지 않은 장면은 부모 판정을 물려받았다 (호출 없음).
  - 실제 FLUX 편집 결과: 유지 요소 8건(인물 모습·동작, 배경, 조명, 컵 형태) 모두 PASS. 같은 장면의 SSIM 은 0.709·0.880 으로 FAIL 이었다.
  - 클로즈업 장면의 `mood: warm lighting` 을 3프레임 중 2프레임에서 "neutral/cooler lighting" 으로 판정해 FAIL(0.33)을 줬다.
    Fake 로는 드러나지 않던 장면 조건의 어긋남이다.
  - 요구대로 나온 4장면 영상 둘(3·5회차의 원본): 요구조건 17건·18건 모두 PASS. 오경보가 없었다.
  - 색을 바꾼 뒤의 오판: 3회차에서 `scene_2:red_mug:color` 가 FAIL(화면은 청록, 답은 "teal, not red").
    예전 값을 알리게 고친 뒤 같은 원본·같은 요청의 4회차는 18/18 이었다.
  - 유지 요소 판정을 고치기 전과 뒤, 같은 클립: 새로 생성된 두 장면이 8건 모두 PASS(3회차) → 4건 FAIL(5회차:
    인물의 동작, 클로즈업의 배경·조명·컵 형태). 실제 편집 결과(4회차)는 고친 판정에서도 4건 모두 PASS 였다.
