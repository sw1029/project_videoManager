# ADR-0021 일시적인 사정으로 낸 결과는 요청의 키에 남기지 않는다 (임시 결과)

- 상태: 채택 (2026-11-12)
- 관련: US-01 (AC-01), ADR-0011 (재과금 방지) · 0013 (생성 캐시·작업 원장) · 0016 (부모 클립 편집) · 0020 (계획의 생성 방식 미리보기)
- 검토 기록: [docs/research/concept-ux-review.md](../research/concept-ux-review.md) §6.3·§7 (B10)

## 맥락
- 부모 클립 편집(ADR-0016)은 부모 영상의 저장본 주소가 있어야 된다. 주소가 없으면 제출하지 않고 장면을 새로 생성한다.
- 그렇게 만든 결과를 **편집 요청의 키**(조건 + 부모 클립)로 작업 원장과 생성 캐시에 남겼다. 거절된 편집을 또 시도하지 않고
  같은 장면을 두 번 생성하지 않기 위해서다 (1차 실호출에서 편집 설정만 바꾼 실행이 같은 장면을 또 생성한 적이 있다).
- 그런데 주소가 없는 까닭은 두 가지다. 저장본이 없거나 만료된 것은 나아지지 않는다. 방금 끝난 작업의 주소가 아직 나오지 않은 것은
  몇 분 뒤면 나아진다 (2차 실호출: Wan 3.0 은 끝난 뒤 2~18분).
- 뒤의 경우에도 결과를 편집 키에 남기니, 주소가 나온 뒤 같은 수정을 다시 실행해도 앞선 새로 생성 결과를 다시 썼다.
  변경 계획이 그 장면을 `EDIT` 라고 알려 준 뒤라면(ADR-0020) 계획과 실행이 어긋난다.

## 결정

### 1. 임시 결과라는 표시 (`provisional`)
- 생성기는 **요청한 방식으로 만들지 못했고 그 사정이 일시적인** 결과의 클립 메타데이터에 `provisional: true` 를 남긴다.
  "이 요청의 결과 키로는 남기지 않는다. 다음에 같은 요청이 오면 다시 시도한다" 는 뜻이다. 포트 계약(`VideoGenerator`)에 적었다.
- 생성 캐시(`CachingVideoGenerator`)는 이 표시가 있는 클립을 저장하지 않는다. 캐시는 편집이 무엇인지 모른다. 표시만 본다.
- 화면에는 `ir.scenes[].clip_production.provisional` 로 나간다. true 면 부모 버전에서 같은 수정을 다시 실행했을 때 편집으로
  만들 수 있다 (계획으로 먼저 확인한다).

### 2. OpenRouter 어댑터: 조건 키로만 남기고 편집 키는 비운다
- 부모 작업이 끝났는데 저장본 주소가 조회 시간 안에 오지 않은 경우만 일시적으로 본다 (`edit.transient`).
  저장본이 없거나 만료된 경우, 편집 요청이 접수 전에 거절된 경우는 지금까지와 같다.
- 새로 생성한 결과는 **조건 키**(조건 + 정체성 기준 + 유지 요소)로 남긴다. 편집을 끈 설정이 만들었을 결과와 같기 때문이다.
  편집 시도 기록과 임시 표시는 그 사본에 싣지 않는다.
- 편집 요청의 키는 `released` 로 비운다. 작업 원장의 새 상태다: 끝났지만 결과를 이 키에 남기지 않음. 이어 받지 않는다.
- 다음에 같은 요청이 오면
  - 주소가 나와 있으면 편집한다.
  - 여전히 없으면 조건 키의 결과를 다시 쓴다 (또 생성하지 않는다). 이때도 편집 키에는 남기지 않는다.
- 대체 사유의 문구를 경우에 따라 나눴다: "저장본 주소가 아직 나오지 않음 … 같은 수정을 다시 요청하면 편집을 다시 시도함" /
  "저장본이 없거나 만료됨".

### 3. 두 번 내지 않기 (ADR-0011·0013 의 원칙은 그대로)
- 새로 생성하는 작업을 접수하면 지금까지처럼 **편집 요청의 키로** 접수 기록을 남긴다. 끊긴 뒤 같은 요청이 오면 주소가 나와 있더라도
  그 작업을 이어 받는다 (편집을 새로 제출하지 않는다). 결과는 그때 조건 키로 옮기고 편집 키를 비운다.
- 조건 키에 먼저 쓰고 나서 편집 키를 비운다. 그 사이에 끊기면 편집 키의 접수 기록으로 이어 받아 다시 한다 (내려받기만 다시 한다).
- 조건 키로 다른 작업이 진행 중이면 그 항목을 덮어쓰지 않는다. 그때는 이 결과를 가리키는 곳이 편집 키뿐이므로 비우지 않고
  임시 표시도 하지 않는다 (지금까지와 같은 동작이다. 비우면 다음 요청이 또 생성한다).
- 조건 키로 옮긴 결과의 클립 파일이 지워져 있으면 새로 생성하지 않고 그 작업의 결과를 다시 내려받는다 (ADR-0013 의 규칙).
  편집 키를 비우기 전에는 그 키의 완료 기록으로 그렇게 했으므로, 비운 뒤에는 조건 키의 기록으로 한다.

## 결과
- 방금 만든 영상을 바로 수정해 새로 생성됐더라도, 주소가 나온 뒤 부모 버전에서 같은 수정을 다시 실행하면 편집으로 만들어진다.
  계획이 `EDIT` 라고 알려 준 대로 된다.
- 같은 장면을 두 번 생성하지 않는 것은 그대로다. 주소가 계속 없으면 조건 키의 결과를 다시 쓰고, 접수된 작업은 이어 받는다.
- 한계
  - 조건 키로 다른 작업이 진행 중일 때 끝난 일시적 대체 결과는 예전처럼 편집 키에 남는다 (드문 경합).
  - 이 변경 전에 편집 키로 남은 결과는 그대로다 (작업 원장은 24시간, 생성 캐시는 지울 때까지).
  - 임시 결과를 받은 수정 버전 자체는 바뀌지 않는다. 편집으로 만들려면 부모 버전에서 같은 수정을 다시 실행해 새 수정 버전을 만든다.
  - '일시적' 의 판단은 OpenRouter 의 상태 응답 모양에 기댄다 (끝난 작업인데 `urls` 가 없음). 다른 생성기는 스스로 정해야 한다.

## 대안
- 일시적 대체 작업을 처음부터 조건 키로 접수하기: 끊긴 뒤 주소가 나와 있으면 편집을 새로 제출해 두 번 내게 된다.
  막으려면 편집을 시도하기 전에 조건 키의 진행 중인 작업을 이어 받아야 하는데, 그러면 편집 요청이 남의 진행 중인 작업
  (편집을 끈 설정이 낸 것)에 묶인다. 접수 기록은 편집 키에 두고 끝난 뒤에 옮기는 쪽이 지금의 규칙을 덜 건드린다.
- 생성 캐시가 `edit.applied` 를 보고 판단하기: 캐시가 편집이라는 개념을 알게 된다. 생성기가 붙이는 표시 하나로 뒀다.
- 주소가 나올 때까지 기다렸다가 편집하기: 설정으로 이미 된다 (`FRAME_VIDEO_EDIT_PARENT_WAIT_S`). 기다릴지는 사용자가 계획을 보고 고른다 (ADR-0020).
- 임시 결과를 받은 수정 버전을 나중에 자동으로 편집본으로 바꾸기: 만든 버전은 바꾸지 않는다는 규칙과 어긋난다.

## 검증
- 단위 테스트 (네트워크 없이)
  - `tests/unit/generator/test_openrouter_edit.py`: 다음 요청에서 편집, 편집 키는 `released`·조건 키는 `completed`,
    주소가 계속 없으면 재사용, 편집을 끈 설정의 재사용, 끊긴 작업 이어 받기, 저장본이 없거나 만료된 경우와 거절된 편집은 그대로,
    조건 키로 다른 작업이 진행 중일 때, 클립 파일이 지워졌을 때 다시 내려받기.
  - `tests/unit/generator/test_generation_cache.py`: 임시 결과는 캐시하지 않는다. `tests/unit/test_clip_production.py`: 화면용 표시.
- 통합 테스트 (루프백 가짜 OpenRouter, 생성 캐시·작업 원장을 모두 켬): `tests/integration/test_consistency_api_flow.py` —
  주소가 없어 새로 생성(`provisional`) → 주소가 나온 뒤 같은 수정을 다시 실행하면 편집 → 한 번 더 실행하면 편집 결과를 다시 씀.
  이 변경 전의 코드로 같은 흐름을 돌리면 두 번째 실행이 `GENERATED` 였다 (계획은 `EDIT` 라고 답했는데도).
- 실제 호출로는 확인하지 않았다. 주소가 없는 상태를 실제 API 에서 다시 만들려면 장면을 새로 생성해야 하고(과금), 주소가 나오는 때를
  맞출 수 없다. 2차 3회차에서 그 상태를 실제로 겪었고, 테스트는 그때의 응답 모양(끝난 작업, `urls` 없음)을 그대로 쓴다.
