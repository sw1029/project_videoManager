# ADR-0015 장면 사이 객체 일관성: 정체성 기준 이미지와 실제 일관성 검수기

- 상태: 채택 (2026-11-12)
- 관련: US-03 (AC-31·32·33), 성공 지표 3 "고정 속성 유지율 90% 이상", ADR-0003·0011·0013
- 조사·실험 기록: [docs/research/character-consistency.md](../research/character-consistency.md)

## 맥락
- 생성은 장면 단위다 (ADR-0003). 2026-11-11 실호출에서 같은 객체(바리스타)가 장면 1 과 장면 3 에서 서로 다른 인물로 나왔다.
  장면마다 모델을 따로 부르고, 장면 사이에 공유하는 것은 글(객체 설명)과 seed 뿐이기 때문이다.
- Fake 일관성 검수기는 클립을 보지 않아 이 결과에 1.0 을 줬다. 지표 3 을 재는 수단이 없었다.
- 과제 문서는 일관성 저하를 리스크 3 으로 꼽고 대응을 "마스크·참고 조건을 고정" 으로 적었다 (문제정의서 §4.3).
  지표 3 의 측정 방법은 "객체가 보이는 표본 프레임 중 지정 색상·형상을 유지한 비율" 이다.
- 선행 연구의 공통된 방법은 객체별 시각 기억이다: 참조 이미지를 받는 영상 모델(reference-to-video)에
  객체마다 기준 이미지를 넘기고, 여러 장면에서는 그 기준을 객체 단위 기억으로 유지한다 (연구 문서 §3).
  OpenRouter 의 Wan 3.0 은 `input_references` 로 참조 이미지를 받는다.
- 제약: GPU·큰 패키지 없이(.venv 에 numpy·torch 없음) API 와 ffmpeg 로 동작해야 하고,
  선택적 재생성(바뀌지 않은 장면은 부모 클립 재사용)을 깨지 않아야 한다.

## 결정

### 1. 정체성 기준 이미지 (`FRAME_IDENTITY`, 기본 off)
- 객체마다 기준 이미지를 하나 둔다. 사용자 참조 이미지(`entity_key` 지정)가 있으면 그것이 기준이고,
  없으면 **그 객체가 나온 클립에서 뽑는다** (`ReferenceImage.origin = DERIVED`).
  뽑은 기준은 버전의 참조 이미지로 저장하고 수정 버전이 물려받는다.
- 그 객체가 나오는 **다른 장면을 생성할 때** `SceneGenerationRequest.identity_references` 로 넘긴다.
  OpenRouter 어댑터는 사용자 참조 다음에 `input_references` 로 보내고, 프롬프트에 `Image N` 지칭·외형 설명·일관성 문장을 넣는다.
- 뽑는 시점
  1. 생성 전에, 이미 손에 있는 클립에서: 재사용할 장면의 클립, 다시 만들 장면의 부모 클립(외형 조건이 그대로인 객체만).
  2. 새로 만든 클립에서: 아직 쓸 기준이 없는 객체만.
  그래서 원본 버전에서는 첫 등장 장면이 기준이 되고, 수정 버전에서는 다시 만드는 장면도 부모와 같은 모습을 이어 간다.
- 추출기(`IdentityReferenceExtractor`): `frame`(클립 가운데 프레임 전체, ffmpeg), `vlm_crop`(VLM 이 짚은 박스로 잘라 냄), `fake`.
  실호출에서 드러난 제약을 `vlm_crop` 에 반영했다.
  - 인물은 머리·어깨까지만 자른다 (세로를 가로의 1.1배까지). 박스 전체를 자르면 손에 든 물건이 함께 들어가 다른 장면에 나온다.
    Wan 은 참조 이미지 한 장에 인물 한 명만 허용한다.
  - 작은 이미지는 짧은 변 480 px 까지 키운다 (Wan 은 한 변 240 px 이상을 요구하고, 모자라면 접수 뒤 작업이 실패한다).
    원래 크기가 96 px 에 못 미치는 조각은 쓰지 않는다.
  - 객체가 안 보이면 다른 시각의 프레임을 한 번 더 본 뒤 건너뛴다.
  - **요구한 고정 속성과 분명히 다르게 나온 객체는 기준으로 쓰지 않는다** (`FRAME_IDENTITY_VERIFY_ATTRIBUTES`, 기본 켬).
    위치를 묻는 같은 호출에서 그 장면의 고정 속성마다 yes / no / unclear 를 받고, no 가 하나라도 있으면 자르지 않는다.
    잘못 나온 모습이 기준이 되면 그 객체가 나오는 다음 장면으로 번지기 때문이다 ("검증").
    판단할 수 없는 속성(unclear)으로는 거르지 않고, 물어본 속성에 대한 판정만 쓴다 (행동 같은 일시적 조건은 묻지 않는다).
    거른 것도 색인에 적어 그 클립에서는 다시 묻지 않는다. 다시 물으면 답이 흔들려 기준이 될 수 있다.
    확인 없이 뽑아 둔 기준은 확인을 켠 뒤에는 다시 쓰지 않는다.
  - 같은 클립·같은 객체의 기준은 한 번만 뽑는다. 뽑은 기준을 색인(`references/identity/<클립 해시>/<객체>.json`)에 적어 두고,
    다시 요청받으면 VLM 을 부르지 않고 그 이미지를 돌려준다. VLM 이 짚는 박스는 호출마다 조금씩 달라서, 다시 뽑으면
    기준 이미지(=생성 키, §3)가 달라져 이미 만든 장면을 또 생성하기 때문이다. 자르는 설정이 바뀌면 다시 뽑는다.
- 추출이 실패해도 생성은 계속한다 (기록만). 기준 이미지는 보조 수단이다.

### 2. 유효성·충돌 규칙 (`domain/services/identity.py`)
- **고정 속성** = 객체의 속성 조건 중 관계 술어와 일시적 술어(행동·자세·표정·위치)를 뺀 것.
  외형 fingerprint = 객체 정의(종류·설명) + 기준 장면에서의 고정 속성.
- **유효성**: 기준을 뽑은 장면에서 객체의 외형 fingerprint 가 뽑을 때 그대로일 때만 쓴다.
  수정으로 외형이 바뀐 객체(컵 색 변경)의 옛 기준은 쓰지 않고 새 클립에서 다시 뽑는다. 수정한 값이 참조와 어긋나면 수정이 반영되지 않는다.
- **충돌**: 기준 장면과 대상 장면이 같은 고정 속성에 다른 값을 요구하면(장면 한정 수정) 그 장면에는 넘기지 않는다.
- **자기 자신**: 기준을 뽑아낸 바로 그 클립(같은 장면·같은 조건)을 만드는 요청에는 넘기지 않는다.
- 종류 우선순위(인물 → 동물 → 소품 → 기타, `FRAME_IDENTITY_KINDS`)로 요청당 `FRAME_IDENTITY_MAX_REFERENCES`(3)개까지.
  배경·문구는 기본으로 뺀다.

### 3. fingerprint·캐시·원장 (ADR-0003·0013 보완)
- `fingerprint`(조건 해시)는 **그대로**다: 장면 조건 + 객체 정의 + 사용자 참조 이미지 + seed. 정체성 기준은 넣지 않는다.
  재사용 판단은 조건만 보므로, 기준 이미지가 생기거나 바뀌어도 조건이 같은 장면은 부모 클립을 그대로 쓴다.
- 생성 캐시·작업 원장의 키는 `VideoGenerator.result_key(request)` + 프로필이다. 기본값은
  `generation_fingerprint` = 조건 + 정체성 기준(URI·객체·외형 설명)이고, 기준이 없으면 `fingerprint` 와 같다 (예전 키와 호환).
- 기준 이미지 파일 이름에는 내용 해시가 들어간다. URI 가 같으면 내용도 같다.
- 새 기준은 클립과 같은 트랜잭션으로 저장한다. 재시작 복구로 다시 실행할 때, 이 버전이 앞선 시도에서 만든 클립은
  조건이 같으면 다시 만들지 않는다 (기준 집합이 달라져도 같은 장면을 두 번 과금하지 않는다).

### 4. 실제 검수기
- `vlm_consistency` (CONSISTENCY): 지표 3 의 정의대로 잰다. 객체가 나오는 장면마다 표본 프레임을 뽑고(기본 장면당 3장),
  객체 하나당 한 번 VLM 에 프레임별로 묻는다: 보이는가 / 기준과 같은 인물·물건인가 / 지정한 고정 속성을 유지하는가.
  기준은 사용자 참조 이미지, 없으면 객체가 보이는 첫 프레임. 점수 = 유지한 프레임 ÷ 판정된 프레임, 0.9 이상이면 PASS.
  어긋난 프레임이 대표하는 구간이 경고 구간이다 (AC-33). 판정 불가는 UNDETERMINED 이고 버전은 COMPLETED 다.
  검수기는 생성 쪽 기준 이미지를 쓰지 않는다 (측정이 방법에 기대지 않게).
- `ssim_preservation` (PRESERVATION): ADR-0016.
- 이미지를 읽는 모델은 `FRAME_VLM_MODEL` (비우면 `FRAME_LLM_MODEL`), 공급자·키는 `FRAME_LLM_*` 를 쓴다.
  LLM 포트의 `complete_json(images=...)` 로 프레임을 보낸다.

## 결과
- 켜면 객체가 두 장면 이상 나오는 영상에서 첫 등장 뒤 장면이 기준 이미지를 참조로 받는다. 끄면 예전과 완전히 같다.
- 비용: 기준 추출은 새로 만든 장면마다 VLM 한 번(`vlm_crop`), 검수는 객체마다 VLM 한 번. 영상 생성 횟수는 늘지 않는다.
  다만 기준을 쓰는 장면은 캐시 키가 달라, 기준 없이 만들어 둔 클립이 캐시에 있어도 다시 생성한다.
- 한계
  - 첫 등장 장면은 기준 없이 만들어진다. 그 장면의 모습이 마음에 들지 않으면 사용자 참조 이미지를 줘야 한다.
  - 외형이 바뀐 객체는 기준을 다시 뽑으므로, 인물의 옷 색을 바꾸면 얼굴도 바뀔 수 있다 (부모 클립 편집 ADR-0016 이 맡는다).
  - 참조를 얼마나 따르는지는 모델에 달렸다. 기준 이미지에 함께 들어간 것은 결과에도 나온다 (참조 누출, "검증").
    요청하지 않은 객체가 나왔는지는 지금 어떤 검수도 보지 않는다.
  - 고정 속성 확인은 VLM 한 번의 판정에 기댄다. VLM 이 다르다고 답하지 않으면 잘못 나온 객체도 기준이 되고,
    잘못 거르면 그 객체는 그 클립에서 기준을 얻지 못한다 (다음 장면의 클립에서 다시 시도한다).
    실제 모델로는 저장된 클립 4개에서 한 번씩만 봤다 ("검증"). 문제가 되면 `FRAME_IDENTITY_VERIFY_ATTRIBUTES=false` 로 끈다.
  - VLM 판정은 같은 입력에도 흔들리고("검증": 같은 클립에 0.5 와 0.83), 미세한 얼굴 차이에는 얼굴 임베딩보다 둔하다.
  - 한 객체의 속성이 일부 장면에만 지정되면(예: 문구는 클로즈업에만) 장면 사이 불일치로 판정된다. 구조화 단계의 문제다.
  - 장면 생성이 앞 장면 결과에 의존하게 되어 장면 병렬 제출과는 순서를 맞춰야 한다 (기준을 뽑는 장면 먼저).
  - 기준 이미지가 달라지면(추출 설정을 바꿔 다시 뽑은 경우 포함) 그 기준을 쓰는 장면의 생성 키가 달라져 다시 생성한다.

## 대안
- 얼굴·DINO·CLIP 임베딩 유사도로 측정: 문헌의 표준 지표지만 torch 또는 onnxruntime + 모델 파일 설치가 필요하다.
  이번에는 설치 없이 되는 VLM 판정을 골랐고, 후속으로 남긴다 (연구 문서 §7).
- 기준 이미지를 fingerprint 에 포함: 기준이 생기는 순간 조건이 같은 장면의 fingerprint 가 달라져 부모 클립 재사용이 깨진다. 기각.
- 이미지 생성 모델로 객체 시트를 먼저 만들기(EntityMem 방식): 첫 장면부터 같은 기준을 쓸 수 있지만 이미지 생성 포트·비용이 더 든다. 후속.
- 장면마다 첫 프레임 이미지를 만들어 image-to-video 로 생성(키프레임 우선): 일관성은 가장 강하지만 파이프라인 구조를 바꾼다. 후속.
- 프롬프트만 강화(외형 설명 반복): 옷·머리 색 같은 거친 속성만 맞고 정체성은 맞지 않는다. 기준 이미지와 함께 쓴다.
