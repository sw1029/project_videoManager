# ADR-0032 컴퓨터에 묶인 경로와 값의 사본을 두지 않는다: 절대 경로 금지 · 설정값은 출처 하나 · 이름 없는 수 금지

- 상태: 채택 (2026-11-15)
- 관련: 백엔드 감사 보고서(`docs/audit/2026-11-backend-audit.md` §12.2 P-19), ADR-0030 (CI 품질 게이트와 기준선 방식),
  ADR-0031 (개념 단위 배치), 검사 안내 `docs/CI.md`

## 맥락
- 기준 (사용자, 2026-11-14): 세션들 사이의 진행에서 **절대 경로 사용과 로직 하드 코딩을 지양한다.**
- 합쳐진 dev 를 훑어 보니 세 가지가 있었다 (보고서 P-19).
  - **컴퓨터에 묶인 경로**: 키 파일의 예시가 개발자 컴퓨터의 드라이브 경로였다 (설정 예시 · README · 도구의 머리말 등 다섯 곳).
    테스트 값에 드라이브 경로와 실제 사용자 이름이 있었고, 번들 도구가 PATH 를 코드에 적어 둔 시스템 폴더로 만들었다.
    모두 51줄이고 그 가운데 고칠 것이 13줄이었다.
  - **같은 값의 사본**: 설정(`Settings`)의 기본값 25개가 어댑터 생성자의 기본값으로 한 번 더 적혀 있었다. 값은 모두 같았지만 손으로 맞춘 것이었다.
    서비스 주소와 모델 id 는 상수로도 한 벌 더 있었다. 계층을 건너 손으로 맞춘 값도 있었다 — 보존 검수의 측정 방법 이름(검수기와 평가),
    장면 길이의 하한 500 과 3000 (각각 두 곳), 업로드 크기의 상한 (두 곳), 녹음 빠르기의 범위 (도메인과 포트).
  - **이름 없는 수**: 비교식에 상태 코드 · 상한 · 임계값이 수로 적혀 있었다 (38곳).
- 이런 것은 리뷰로는 지켜지지 않는다. 값이 같을 때는 눈에 띄지 않고, 한쪽만 바뀐 뒤에야 드러난다.

## 결정

### 1. 컴퓨터에 묶인 절대 경로를 커밋하지 않는다
- 대상은 저장소에 커밋되는 글 전부다: `src` · `tests` · `scripts` · `docs` · `docker` · `.github` 와 뿌리의 설정 · 문서.
  화면(`frontend/`)은 이 결정의 범위 밖이다.
- 드라이브 문자로 시작하는 경로와, 홈 · 설치 · 임시 폴더에서 시작하는 경로를 적지 않는다. 대신 쓰는 것:
  설정(환경 변수), 저장소 기준 상대 경로, 테스트의 `tmp_path`, 운영체제가 알려 주는 값(`os.environ` · `os.confstr` · 탐색),
  문서의 자리표시 (`path/to/openai.key`).
- 허용하는 것은 네 가지뿐이고, 검사의 허용 목록에 (파일 · 이유 · 그 줄의 글)로 적는다.
  1. 경로를 거절 · 변환 · 가리는지 시험하는 입력
  2. 컨테이너 안의 경로
  3. 규격이 정한 위치 (XDG Base Directory 의 기본값, macOS 의 글꼴 폴더)
  4. 사람에게 보이는 안내 · 설명의 예시
- 사용자 이름이 들어가는 예시에는 실제 이름이 아니라 중립 이름(`someone`)을 쓴다.

### 2. 설정값은 출처 하나
- **설정에서 오는 값의 기본값은 설정(`config/settings.py` · `config/theme_settings.py`)에만 있다.**
  조립(`config/`)이 어댑터 · 유스케이스를 만들 때 그 값을 인자로 넘기고, 받는 쪽 생성자는 그 인자에 기본값을 두지 않는다
  ('없음' 을 뜻하는 `None` 은 된다). 그 클래스를 직접 만드는 코드는 — 테스트도 — 값을 직접 준다.
- 설정의 주소 · 모델 기본값(이름이 `_url` · `_model` 로 끝나는 항목)은 `frame/config/` 밖의 코드에 다시 적지 않는다.
- 설정에 없는 값(어댑터 안의 조정값)은 그 어댑터가 출처다. 여러 모듈이 쓰면 이름 붙은 상수 하나를 두고 가져다 쓴다.
- 계층을 건너 같은 값을 써야 하면 **둘 다 볼 수 있는 안쪽 계층에 하나**를 둔다. 바깥 계층은 안쪽을 import 할 수 있으므로 값을 다시 적을 까닭이 없다.

  | 값 | 자리 | 쓰는 곳 |
  |---|---|---|
  | 보존 검수의 측정 방법 이름 (`vlm_keep` · `ssim` · `identical`) | `domain/checks.py` | 보존 검수기 둘, 지표 1 평가, 평가 도구 |
  | 장면 길이의 하한 (`MIN_SCENE_MS` · `MIN_PLANNED_SCENE_MS`) | `domain/ir.py` | 구조화의 보정과 프롬프트, IR 입력 스키마, 테마의 장면 자리 |
  | 녹음 빠르기의 범위 (`MIN_TRACK_TEMPO` · `MAX_TRACK_TEMPO`) | `domain/series/narration.py` | 녹음 맞추기, 소리 편집 포트의 `TrackCut` |

### 3. 비교식에 이름 없는 수를 쓰지 않는다
- 상태 코드는 `http.HTTPStatus`, 상한 · 임계값 · 길이는 뜻(단위 · 근거)을 적은 이름 붙은 상수로 쓴다.
- 0 과 1 은 그대로 쓴다. "둘 미만" 은 "하나 이하" 로 적는다 (`len(x) <= 1`) — 상수를 만들 만한 값이 아니다.
- 테스트는 예외다: 기대하는 값을 수로 직접 견준다.

### 4. 지키는 검사 (ADR-0030 의 방식)

| 검사 | 무엇을 막나 | 걸리면 |
|---|---|---|
| `tests/architecture/test_machine_paths.py` | 컴퓨터에 묶인 절대 경로가 새로 커밋되는 것 | 경로를 없앤다. 꼭 있어야 하면 그 파일의 `ALLOWED` 에 이유와 함께 적는다. 허용한 줄이 없어지면 목록에서도 지워야 통과한다 |
| `tests/architecture/test_settings_single_source.py` | 조립이 설정에서 넘기는 인자에 생성자 기본값이 생기는 것, 설정의 주소 · 모델 기본값이 `frame/config/` 밖에 다시 적히는 것 | 기본값을 지우고 값은 조립이 넘긴다 |
| ruff `PLR2004` (`src` · `scripts`) | 비교식의 이름 없는 수 | 이름 붙은 상수로 |

- 둘째 검사는 짝(어느 설정 항목이 어느 생성자의 어느 인자로 가는가)을 조립 코드에서 스스로 찾는다 — 지금 46짝. 표를 손으로 맞추지 않는다.
- 기준선(`tests/architecture/baselines.py` 의 `SETTINGS_ARGUMENTS_WITH_DEFAULTS`)은 비어 있다. 켤 때 걸리던 25개를 모두 고쳤다.

## 결과
- 설정의 기본값을 바꾸면 그 값을 쓰는 모든 곳이 따라 바뀐다. 한쪽만 바뀌는 일이 없다.
- 어댑터를 직접 만드는 테스트는 값을 직접 적어야 한다. 테스트가 무엇을 가정하는지 드러나는 대신 호출이 길어진다.
  한 파일에서 여러 번 만드는 곳은 그 파일의 작은 도우미가 채운다.
- 키 파일의 예시가 자리표시가 되어, 문서를 그대로 따라 하면 "키 파일이 없습니다" 가 나온다. 자기 경로로 바꾸라는 뜻이 드러난다.
- 절대 경로 검사는 글을 훑는 것이라 놓치는 모양이 있을 수 있다 (조각을 이어 붙여 만든 경로 등). 그런 것이 보이면 식을 넓힌다.
- 서버의 동작은 바뀌지 않았다. 조립은 전부터 모든 값을 설정에서 넘기고 있었다.

## 대안
- **생성자 기본값을 남기고 "설정의 기본값과 같은지" 만 검사한다**: 고칠 것이 적지만 같은 값이 두 곳에 남는다. 값을 바꿀 때 두 곳을 고쳐야 하고,
  검사가 주는 것은 '어긋나면 안다' 뿐이다. 시리즈 · 음성 어댑터가 이미 기본값 없이 받고 있어 한 방식으로 맞췄다.
- **설정이 어댑터의 상수를 가져다 쓴다** (기본값의 출처를 어댑터로): 설정 모듈이 어댑터 패키지를 import 하게 되고,
  값이 어디서 정해지는가의 답이 설정이 아니게 된다.
- **절대 경로를 리뷰로만 본다**: 지금까지 그렇게 했고 51줄이 쌓였다.
