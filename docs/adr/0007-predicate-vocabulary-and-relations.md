# ADR-0007 술어 어휘, 관계 조건 규칙, 장면 타임라인 검증

- 상태: 채택 (2026-11-07, 2차 스키마 검토 반영)

## 맥락
1차 스켈레톤의 IR 스키마에서 네 가지 결함이 확인되었다.
1. 요구조건 키가 `장면:객체:술어` 라서 한 객체가 같은 장면에서 두 관계(holds cup, holds phone)를 가지면 충돌했다. 도메인 검증은 통과하고 SQL 저장소만 UNIQUE 위반으로 거부해 저장소에 따라 결과가 달랐다.
2. 관계 조건을 수정하면 값(expected_value)만 바뀌고 상대 객체(related_entity_key)는 남아 둘이 어긋났다.
3. 장면이 겹치거나 비어 있어도 검증을 통과했다. 조립기는 장면을 순서대로 이어 붙이므로 타임라인이 영상과 어긋난다.
4. 술어가 자유 문자열이라 `color`/`colour`/`색상` 이 서로 다른 조건이 되고, 검수기가 쓸 값 종류 정보가 없었다.

## 결정
- **술어 어휘** (`domain/vocabulary.py`): 대표 이름·별칭·값 종류(COLOR/TEXT/NUMBER/POSITION/ENTITY)·관계 여부를 등록한다.
  - 보완 (2026-11-14, 감사 D-07): 값 종류는 여섯이다. ADR-0008 이 `LITERAL` (화면 문구·브랜드 — 철자를 그대로 둔다)을 더했다.
  `RequirementSpec` 과 `AttributeChange` 는 생성 시점에 술어를 정규화한다(소문자, 공백/하이픈 → `_`, 별칭 → 대표 이름).
  등록되지 않은 술어도 정규화 뒤 허용한다(확장성). 어휘는 `GET /api/vocabulary/predicates` 로 화면에 제공한다.
- **관계 조건 규칙**: 관계 술어는 `related_entity_key` 가 필수이고 `expected_value` 는 상대 객체 키와 같다(비어 있으면 자동 보충).
  속성 술어는 상대 객체를 가질 수 없다. 자기 자신과의 관계는 금지한다.
- **요구조건 키**: `장면:객체:술어[:상대객체]`. 장면 안에서 중복 키는 검증 오류다. SQL 의 `requirement_id` 도 같은 키에서 파생된다.
- **수정 전파**: 관계 술어의 변경은 상대 객체를 바꾼다(새 상대 객체는 그 장면에 연결되어 있어야 함).
  같은 (객체, 술어) 조건이 여러 개면 `current_value` 로 바꿀 대상을 지정해야 하며, 지정한 현재 값이 없는 장면은 건드리지 않는다.
- **타임라인**: 장면은 0 ms 에서 시작하고 겹침·빈 구간 없이 이어져야 한다. 구조화 유스케이스는 장면 길이 합계가 목표 길이와
  허용 오차(500 ms 또는 10% 중 큰 값) 안에 있는지 확인한다.
- **장면 수준 조건**: `entity_key=None` 인 요구조건(분위기·조명·카메라). DSL 은 `scene.mood = calm @ a` 로 쓴다.
- **schema_version**: IR 문서에 버전 필드를 넣어 이후 형식 변경(요구조건 단위 시간 구간 등)에 대비한다.

## 결과
- 메모리·SQL 저장소가 같은 입력에 같은 판정을 내린다 (계약 테스트로 보장).
- 화면은 어휘 API 로 속성 블록을 구성하고, 응답의 `value_kind`/`relational` 로 편집기 종류를 고를 수 있다.
- 비용: LLM 어댑터는 어휘와 타임라인 규칙을 프롬프트에 포함해야 한다(`build_system_prompt` 가 자동 생성).
- 남은 과제: 요구조건 단위 시간 구간(장면 내부 구간), 술어별 값 형식 검증(HEX 색상·좌표), JSON Schema 내보내기.
