# ADR-0035 인물 일관성은 실제 영상 생성기에서 기본으로 켠다 (FRAME_IDENTITY=auto)

- 상태: 채택 (2026-11-19)
- 관련: ADR-0015 (정체성 기준 이미지·실제 일관성 검수기), ADR-0011 (OpenRouter 영상 생성기), ADR-0019 (변경 요청 해석기의 auto),
  성공 지표 3 "고정 속성 유지율 90% 이상"

## 맥락
- ADR-0015 의 정체성 기준 이미지는 `FRAME_IDENTITY` 로 켜야만 쓰였다 (기본 off). 실제 영상 생성기(`external_api`)를 켜도
  따로 켜지 않으면 장면마다 같은 인물이 다른 사람으로 나온다 — 2026-11-11 실호출에서 본 문제다 (바리스타 유지율 0.5).
  vlm_crop 을 켜면 같은 브리프에서 1.0 이었다 (ADR-0015 의 실험).
- 그대로 기본값을 `vlm_crop` 으로 바꾸면 가짜 생성기에서도 VLM 클라이언트를 만든다. 오프라인 시연(키 없음)·CI·테스트는
  OpenAI 키가 없어 기동에 실패하고, 가짜 생성기의 클립(JSON 매니페스트)에는 자를 프레임도 없다.
- 같은 모양의 결정이 이미 있다: 변경 요청 해석기의 `auto` 는 구조화기를 따른다 (ADR-0019, `change_interpreter_key`).

## 결정
- `FRAME_IDENTITY` 의 기본값을 `auto` 로 한다. `container.identity_key` 가 푼다:
  - 생성기가 `fake` 가 아니면(실제 영상) `vlm_crop`, `fake` 면 `off`.
  - 직접 정한 값(`off` · `vlm_crop` · `frame` · `fake`)은 그대로 따른다. 끄려면 `FRAME_IDENTITY=off`.
- `/health` 의 `adapters.identity` 는 푼 값(실제로 쓰는 추출기)을 알린다.
- vlm_crop 의 VLM 을 만들 수 없으면(키 없음) 기동 시점에 실패하되, 메시지에 이 기능이 VLM 을 쓴다는 것과
  키를 주는 곳(`FRAME_LLM_KEY_FILE` · `OPENAI_API_KEY`), 끄는 방법(`FRAME_IDENTITY=off`)을 적는다.
  직접 고르지 않은 사람도 만나는 오류라서다. 조용히 끄지 않는다: 켜졌다고 믿는 기능이 꺼진 채로 돌게 된다.
  화면 키 입력(`FRAME_LLM_RUNTIME_KEY`)을 켠 서버는 키 없이 기동하고, 키가 없을 때의 VLM 호출만 실패한다 (구조화와 같다).

## 결과
- 실제 영상 생성기로 띄우면 따로 설정하지 않아도 객체가 처음 나온 클립에서 기준 이미지를 뽑아 다른 장면에 넘긴다.
  그만큼 VLM 호출(객체·클립마다 한 번, 같은 클립은 색인으로 다시 묻지 않는다)과 시간이 든다:
  기준을 뽑을 클립이 먼저 끝나야 그 객체가 나오는 다음 장면을 만들 수 있다.
- 실제 영상 생성기 + OpenAI 키 없음(규칙 기반 구조화 등)은 이제 기동에 실패한다. 메시지대로 키를 주거나 `off` 로 둔다.
- 가짜 생성기의 동작(오프라인 시연·CI·테스트)은 바뀌지 않는다.
